# 为什么新版废弃了LLMRequestChain
从表面看废弃了LLMRequestChain, 开发者需要通过BeautifulSoup手动去解析返回的查询结果（html），确实增加了开发者的工作量，但这其实是 LangChain 设计理念进化的结果，需要从不同角度来理解这种变化：

**1. 废弃 LLMRequestsChain 的核心原因**
- **安全性考量**：自动爬取网页内容存在法律风险和滥用可能（如违反网站 robots.txt 规则）
- **稳定性问题**：网页结构频繁变动会导致预置解析逻辑失效
- **职责分离**：更专注 LLM 核心功能，将网络请求交给专业库处理

**2. 新版方案的潜在优势**
```python
# 旧版（黑盒操作） 见 ./tools/llmchain-request-deprecated.py
requests_chain = LLMRequestsChain(llm_chain=...)

# 新版（可控解析） 见 ./tools/llmchain-request-new.py
def custom_parser(html: str):
    soup = BeautifulSoup(html, 'html.parser')
    # 可添加异常处理、日志记录等
    return extracted_text
```
- **精确控制**：可针对特定网站优化选择器（如使用 CSS selector `.current-weather`）
- **灵活扩展**：轻松集成反爬机制（如代理轮换、请求头伪装）
- **透明度提升**：明确知道数据如何被处理

**3. 推荐的改进方向**

**4. 折中方案（平衡便捷与可控）**
```python
from langchain_community.document_loaders import AsyncHtmlLoader
from langchain_community.document_transformers import BeautifulSoupTransformer

# 使用 LangChain 官方 HTML 处理工具
urls = ["https://weather.com/chengdu"]
loader = AsyncHtmlLoader(urls)
docs = loader.load()

# 自动提取主要内容
transformer = BeautifulSoupTransformer()
doc_transformed = transformer.transform_documents(
    docs, tags_to_extract=["div"]
)
print(doc_transformed[0].page_content)
```

**5. 架构设计视角的对比**
|                      | 旧版方案                          | 新版方案                          |
|----------------------|---------------------------------|---------------------------------|
| **维护成本**           | 低（但官方停止维护）                 | 需自主维护解析逻辑                   |
| **可解释性**           | 黑盒操作                          | 全流程透明                        |
| **合规性**            | 高风险                           | 可自主添加 robots.txt 检查          |
| **适用场景**           | 快速原型开发                       | 生产环境部署                      |

**总结**：这实际上是框架成熟化的必然过程。虽然短期增加了开发成本，但：
- 避免了因 Google 页面改版导致整个链条崩溃的风险
- 允许结合专业爬虫框架（如 Scrapy、Playwright）
- 符合现代开发中 "显式优于隐式" 的设计哲学

建议在实际项目中：
1. 优先使用官方天气 API
2. 若必须爬取，采用模块化设计将解析逻辑独立封装
3. 使用 LangChain 的 `HTMLHeaderTextSplitter` 等工具辅助处理
```python
from langchain_text_splitters import HTMLHeaderTextSplitter

headers_to_split_on = [("h1", "Header 1")]
splitter = HTMLHeaderTextSplitter(headers_to_split_on=headers_to_split_on)
splits = splitter.split_text(html_content)
```
