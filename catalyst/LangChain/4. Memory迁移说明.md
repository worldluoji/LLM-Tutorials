# Memory迁移说明
旧版 langchain的 ConversationSummaryBufferMemory、ConversationBufferWindowMemory等 Memery工具，在Langchain 0.2.x中已经被弃用，官方建议如下：

As of the v0.3 release of LangChain, we recommend that LangChain users take advantage of LangGraph persistence to incorporate memory into their LangChain application.
- Users that rely on RunnableWithMessageHistory or BaseChatMessageHistory do not need to make any changes, but are encouraged to consider using LangGraph for more complex use cases.
- Users that rely on deprecated memory abstractions from LangChain 0.0.x should follow this guide to upgrade to the new LangGraph persistence feature in LangChain 0.3.x.

参考： https://python.langchain.com/docs/versions/migrating_memory/

即，简单的逻辑可直接使用 RunnableWithMessageHistory or BaseChatMessageHistory，但复杂场景建议使用 LangGraph

## Langgraph和Langchain的关系
Langgraph和Langchain是同一生态系统中互补的工具，共同服务于构建基于大语言模型（LLM）的复杂应用。以下是它们的关系和区别的清晰总结：

### 1. **核心定位**
• **Langchain**：  
  是一个框架，专注于通过“链”（Chains）将多个LLM相关组件（如模型调用、提示模板、记忆模块、数据检索等）串联成线性流程。它适用于需要顺序执行的任务，例如问答系统或文本生成。

• **Langgraph**：  
  是Langchain的扩展，专注于构建**基于图结构的工作流**。它允许定义节点（Node）和边（Edge），支持分支、循环、并行等复杂控制流，适用于需要动态决策（如条件分支、多步骤循环）的应用场景。

### 2. **功能互补**
• **Langchain的局限性**：  
  链式结构是线性的，难以处理需要动态调整流程的任务（例如根据中间结果选择不同分支）。
  
• **Langgraph的增强**：  
  通过图结构扩展了Langchain的能力，使得开发者可以更灵活地设计复杂逻辑（如代理的循环推理、多工具动态调用）。

### 3. **协同工作**
• **组件复用**：  
  Langgraph可以直接使用Langchain的模块（如模型、工具、记忆）作为图中的节点，无需重复开发。
  
• **流程控制**：  
  Langgraph负责管理节点间的执行顺序和条件跳转，而Langchain处理具体任务的执行（如调用API、处理数据）。

### 4. **典型用例**
• **Langchain**：  
  适用于文档分析、简单对话机器人等线性任务。
  
• **Langgraph**：  
  更适合需要复杂逻辑的场景，例如：
  • **自主代理（Agent）**：根据环境反馈循环执行工具调用。
  • **多模型协作**：不同模型按条件分工处理任务。
  • **并行处理**：同时执行多个子任务并聚合结果。

### 5. **总结关系**
• **Langgraph是Langchain生态的增强工具**，两者均由同一团队开发，旨在共同解决LLM应用的多样化需求。
• 使用Langchain构建基础模块（如提示、工具），再通过Langgraph编排复杂流程，能显著提升应用的处理能力和灵活性。
