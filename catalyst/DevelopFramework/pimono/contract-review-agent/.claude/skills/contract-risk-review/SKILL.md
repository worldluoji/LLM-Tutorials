# contract-risk-review

## 核心理念

合同不是走形式，每个字都可能是坑。让 AI 先帮你踩一遍。

风险条款往往藏在语义和逻辑里，而非关键词里：

- "甲方享有最终解释权" — 看上去平淡，实则单方解释条款
- "乙方不得以任何方式提出异议" — "任何方式"是兜底陷阱
- "包括但不限于" — 看似例举，实则无限扩张
- "适当时候"、"合理期限" — 看似公允，实则不可执行

仅靠关键词扫描会漏掉大量真实风险，必须用语义理解 + 上下文判断。

## 工作流程

```
文本提取 → 结构解析 → 语义风险识别 → 风险分级 → 生成修订建议 → 输出审查报告
```

1. **文本提取**：接收 PDF/Word/文本输入，统一转为纯文本（保留章节编号）
2. **结构解析**：识别合同标题、当事方、合同类型、章节结构
3. **语义风险识别**：逐条审查，对照 6 类风险进行语义匹配
4. **风险分级**：按严重程度打 🔴/🟠/🟡 三档
5. **生成修订建议**：从 `references/revision-suggestions.md` 选取或定制替代文本
6. **输出审查报告**：默认 markdown；JSON 模式下只输出纯数组

## 6 类风险类型

| 风险类型 | 识别要点 | 典型表现 |
| --- | --- | --- |
| **不平等条款** | 单方权利、单方解释、单方变更、单方解除 | "甲方享有最终解释权"、"甲方有权单方调整价格"、"甲方可单方解除合同且不担责" |
| **违约责任失衡** | 违约金不对等、免责过宽、举证责任倒置、扣款权无限制 | 甲方违约无责、乙方违约金高达合同额 30% 且无上限、损失赔偿无封顶 |
| **知识产权陷阱** | 成果归属模糊、过度授权（永久/全球/不可撤销）、背景 IP 流失 | "工作成果的全部知识产权归甲方"、"含永久、全球、不可撤销、可转授权许可" |
| **管辖权不利** | 异地诉讼/仲裁、独家仲裁、放弃诉前救济、违反专属管辖 | 约定异地法院、约定独家仲裁、约定放弃管辖异议 |
| **表述模糊** | 数量/期限/标准/责任无量化、"等"字兜底、"合理"无定义 | "适当时候"、"合理期限内"、"包括但不限于"、"等"、"相关" |
| **隐藏义务** | "应/须"叠加隐性义务、连带责任、配合义务无边界 | "乙方应承担因…产生的一切费用"、"乙方对第三方行为负责"、"配合义务"无期限 |

## 默认输出格式（markdown 报告）

```markdown
# 合同风险审查报告

## 基本信息
- 合同类型：
- 当事方：
- 我方角色：甲方 / 乙方
- 审查时间：

## 总体评分：【A / B / C / D】

> A：未发现重大风险，可直接签署
> B：存在轻微风险，建议小幅修订后签署
> C：存在明显风险，必须修订关键条款
> D：存在重大风险，建议拒绝或重新谈判

## 风险概览

| 等级 | 数量 | 主要类型 |
| --- | --- | --- |
| 🔴 高风险 | x | … |
| 🟠 中风险 | x | … |
| 🟡 低风险 | x | … |

## 🔴 高风险条款

### 风险 1：<一句话概括>
- **条款定位**：第 X 条 / 第 X 章 第 X 款
- **原文摘录**："……"
- **风险类型**：xxx
- **风险说明**：……（说明为什么这条对我方不利）
- **修订建议**：
  > "……"（可直接使用的替代文本）

## 🟠 中风险条款
（同上格式）

## 🟡 低风险条款
（同上格式）

## 审查结论
- 总体评价：……
- 必须修订的条款（建议拒绝签署的红线）：……
- 可以谈判让步的条款：……
- 下一步建议：……
```

## JSON 输出模式

当调用方明确要求 JSON 时，**只返回下面的纯 JSON 数组**，不输出任何 markdown 包装、报告标题或解释文字：

```json
[
  {
    "level": "high|medium|low",
    "type": "不平等条款|违约责任失衡|知识产权陷阱|管辖权不利|表述模糊|隐藏义务",
    "clause": "第 X 条 / 章节定位",
    "originalText": "原文摘录",
    "suggestion": "可直接使用的修订文本"
  }
]
```

JSON 模式约束：
- 顶层必须是数组，不要包裹 `{}` 对象
- 不要输出任何 markdown 代码块标记（```）
- 不要在数组前后添加任何说明文字
- 字段名严格使用上面的英文 key

## 我方角色判断规则

合同审查必须明确我方角色后才能判断风险方向：

- **作为甲方**：警惕对方拒绝承担义务、要求单方保护、逃避责任的条款
- **作为乙方**：警惕对方加重的义务、不对等的违约金、对己方不利的管辖

若调用方未指定角色，默认按"乙方"视角审查（多数签约场景下乙方处于弱势），并在报告中标注"建议确认我方角色"。

## 评分规则

- **A**：无 🔴，🟠 0-1 条，🟡 任意
- **B**：无 🔴，🟠 2-3 条
- **C**：🔴 1-2 条，或 🟠 超过 4 条
- **D**：🔴 3 条及以上，或存在单条足以导致重大损失的条款（如无上限违约金、IP 全部流失、独家仲裁 + 异地法院叠加）

设计要求（自检清单）：
1. **语义理解优先** — 不依赖关键词，理解条款真实含义和逻辑陷阱
2. **上下文关联** — 结合合同类型、我方角色判断风险方向
3. **可解释性** — 每个风险点都要有明确理由
4. **实用性** — 给出可直接使用的替代文本，而非泛泛建议
5. **输出克制** — 默认 markdown；JSON 模式下只输出纯数组
