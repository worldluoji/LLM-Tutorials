# Wiki Schema — 投研知识库结构定义

> 本文件定义 Wiki 的页面类型、命名约定、frontmatter 规范、工作流。
> 由你和 LLM 共同迭代演进。当前版本: v1.0

## 三层架构

| 层级 | 路径 | 性质 | 说明 |
|------|------|------|------|
| Raw Sources | `/data/raw/` | 只读，不可变 | 原始资料（PDF / markitdown 转出的 .md / 外部笔记） |
| Wiki | `/data/wiki/` | LLM 读写 | 结构化 Markdown 知识库 |
| Schema | `/data/schema.md` | 本文件 | Wiki 结构与工作流配置 |
| LLM Workspace | `/data/.llm-wiki/` | LLM 读写 | 健康报告、待处理队列、临时索引 |

## 页面类型与命名

| 类型 | 命名格式 | 示例 | 存放位置 |
|------|---------|------|---------|
| 个股档案 | `{6位代码}-{公司简称}.md` | `300750-宁德时代.md` | `/data/wiki/` |
| 行业综述 | `industry-{行业名}.md` | `industry-动力电池.md` | `/data/wiki/` |
| 宏观/概念 | `macro-{概念名}.md` | `macro-美联储加息.md` | `/data/wiki/` |
| 资料摘要 | `source-{代码或关键词}-{年份或日期}.md` | `source-300750-2025年报.md` | `/data/wiki/` |
| 策略/复盘 | `strategy-{策略名}.md` | `strategy-网格交易复盘.md` | `/data/wiki/` |

所有页面统一放在 `/data/wiki/` 根目录（**不分子目录**），便于 Obsidian 图谱视图。

## 关键文件

- **`/data/wiki/index.md`** — 内容总览目录。按类别（个股 / 行业 / 宏观 / 策略 / 资料）组织，每条含 wikilink + 核心逻辑一句话摘要。LLM 每次导入时更新。
- **`/data/wiki/log.md`** — 投研操作日志。按时间倒序追加（新事件在最上方），格式如 `## [YYYY-MM-DD] 操作类型 | 简述 | 涉及实体`。
- **`/data/.llm-wiki/health-report.md`** — 最新一次体检报告，结构化列出链接 / 矛盾 / 时效问题。

## Frontmatter 规范

### 个股页 `300750-宁德时代.md`
```yaml
---
type: stock
code: 300750
name: 宁德时代
industry: 动力电池
tags: [新能源, 锂电池]
created: 2026-08-19
updated: 2026-08-19
sources: [source-300750-2025年报, source-300750-中信建投20260815]
---
```

### 行业页 `industry-动力电池.md`
```yaml
---
type: industry
name: 动力电池
tags: [新能源, 中游制造]
related_stocks: [300750-宁德时代, 002460-赣锋锂业]

```

### 宏观/概念页 `macro-美联储加息.md`

```

code: 300750

```

## 页面章节顺序

### 个股页（固定）
1. **公司画像**（一句话定位 + 主营 + 实际控制人）
2. **核心数据**（最近一份年报的关键指标表格，含同比）
3. **业务结构**（按产品/地区拆分营收占比）
4. **投资逻辑**（驱动因素 3-5 条，每条带来源 wikilink）
5. **关键风险**（每条带来源）
6. **历史观点变更**（按时间倒序追加，标注资料来源）
7. **⚠️ 矛盾标注**（如存在）
8. **来源链接**（列出所有 source-xxx 页面 wikilink）

### 行业页（固定）
1. **行业画像**（一句话定位 + 产业链位置）
2. **关键指标**（行业规模、增速、集中度）
3. **驱动因素**
4. **竞争格局**（含代表个股 wikilink）
5. **政策与监管**
6. **⚠️ 矛盾标注**
7. **来源链接**

### 宏观/概念页（固定）
1. **概念定义**
2. **历史脉络**（按时间倒序）
3. **影响传导**（影响哪些行业 / 个股，含 wikilink）
4. **当前状态**（最新数据 + 来源）
5. **⚠️ 矛盾标注**
6. **来源链接**

### 资料摘要页（固定）
1. **报告基本信息**（发布方、日期、类型、评级）
2. **核心数据**（表格）
3. **主要观点**（3-7 条要点）
4. **关键风险**（如报告有提及）
5. **提取的实体**（wikilink 列表）
6. **相关概念**（wikilink 列表）

### 策略/复盘页（自由结构，但建议包含）
1. **策略概述**
2. **执行记录**（按时间倒序）
3. **复盘结论**
4. **改进方向**
5. **来源链接**

## 交叉引用原则

- **Wikilink** 风格：`[[300750-宁德时代]]` — 支持 Obsidian 图谱视图
- 每个个股页底部都要有"来源"链接，指回资料摘要页
- 摘要页末尾列出"提取的实体"和"相关概念"，形成概念网络
- **标注跨资料关联**：多篇研报提到相似观点时，在页面中明确标注
- **标注矛盾观点**：不同资料的冲突要明确标注，不偷偷覆盖（用 `⚠️ 矛盾` 区块）

## 矛盾处理规则

当两份资料对同一指标得出不同结论时：

1. **不得**静默覆盖其中一方
2. 在相关个股/行业页底部新增：

```
## ⚠️ 矛盾标注

### [指标名]
- 来源 A [[source-xxx-A]]：数值 X，理由...
- 来源 B [[source-xxx-B]]：数值 Y，理由...
- 待解决：人工核实 / 等待更新资料
```

3. 在 `log.md` 中追加 `## [日期] 矛盾登记 | 涉及指标 | 涉及页面`

## 工作流

### 导入新资料的 7 步流程
```
1. markitdown 转换（如 raw 已存在 .md 则跳过）
2. 阅读 raw 文件，识别实体、指标、观点
3. 创建/更新 source-xxx.md 资料摘要页
4. 同步更新涉及的 个股/行业/宏观 页（增量追加，不覆盖）
5. 在 source 页中通过 wikilink 反向引用被更新页
6. 更新 index.md 在对应分类下追加新条目
7. 追加 log.md 操作日志
```

### 健康检查 4 类问题
- **链接完整性**：wikilink 目标文件是否存在
- **矛盾检测**：跨页面同一指标数值是否一致
- **时效性**：资料摘要的 `report_date` 距今是否超过 1 年
- **覆盖度**：个股页是否包含全部固定章节

## 版本演进

本 schema 是活文档。当出现以下情况时更新本文件：
- 新增页面类型
- 新增 frontmatter 字段
- 修改章节顺序
- 修正命名约定

每次更新 schema 后，必须检查并迁移历史页面。
