# MCP的通信方式

> **协议更新（2025）**：MCP 规范在 2025 年版本中已将 **Streamable HTTP** 作为远程传输的推荐方案，原 **SSE（Server-Sent Events）传输已标记为 deprecated**。新集成请优先选择 Streamable HTTP；存量 SSE 服务可通过官方迁移指南升级。

MCP 规范定义了以下几种传输方式：

- **stdio（Standard Input/Output）**：客户端通过启动服务器子进程并使用标准输入（stdin）和标准输出（stdout）建立双向通信，一个服务器进程只能与启动它的客户端通信（1:1 关系）。stdio 适用于本地快速集成的场景。

- **Streamable HTTP（推荐）**：服务器作为独立进程运行，客户端通过普通 HTTP 请求与之交互；当需要流式响应时，服务器可以切到 SSE 通道返回增量事件。兼容多个客户端随时连接和断开，支持无状态 HTTP 请求和有状态会话，是当前官方推荐的远程传输方式。

- **SSE（Server-Sent Events，已废弃）**：旧版远程传输，服务器只能通过长连接 SSE 单向推送事件。新部署请勿再使用，存量服务请规划迁移。

studio示例见：mcp-client-dmeo

MCP Client 与 MCP Server 交互时有两个方法，一个是 list_tool，一个是 call_tool。这两个方法一个是列出所有支持的工具的名称、描述、参数等，另一个则是调用工具。那这是不是就与我们之前学过的 Agent 和 Function Calling 时很类似了呢？

我们使用 Agent 时，也需要先手工撸代码做与 list_tool 同样的事情，然后将结果当作 prompt 喂给大模型，这样大模型才能知道遇到问题时，有什么工具能够解决问题。call_tool 就不说了，属于 Agent 与 Function Calling 的基础操作。

可以看到，MCP通过 list_tool 和 call_tool 两个方法，统一了通信标准。
