# write、edit 和 multiedit 的区别
在 Claude Code 的 `setting.json` 权限配置中，`write`、`edit` 和 `multiedit` 是三种不同粒度的文件修改权限，它们控制着 AI 助手对文件系统进行变更的方式和范围。

## 1. `write` – 写入/覆盖文件
- **含义**：允许创建**新文件**，或**用新内容完全覆盖**一个已存在的文件。
- **典型场景**：
  - 从头生成一个配置文件（如 `config.yaml`）
  - 重写整个模块实现
- **风险**：较高，因为可能不小心覆盖未保存的重要代码。
- **权限控制**：通常建议设为 `ask`（每次询问）或 `deny`（仅手动放行关键路径）。

## 2. `edit` – 局部编辑（单处修改）
- **含义**：允许对**现有文件**进行**一次具体的局部修改**（例如替换一段文本、插入几行代码）。
- **典型场景**：
  - 修复某个函数中的一行 bug
  - 添加一个 import 语句
  - 修改一个配置项的值
- **风险**：中低，因为只是改动文件的一小部分，且一般会带上精确的搜索/替换模式。
- **权限控制**：可设为 `allow`（自动执行常见小修改），`ask` 也常用。

## 3. `multiedit` – 批量编辑（多处修改）
- **含义**：允许在一次操作中对**同一文件的不同位置**或**多个不同文件**同时进行多处编辑。
- **典型场景**：
  - 重命名一个被多处引用的函数（同时改所有调用处）
  - 调整一个组件的 API 签名，并同步更新所有使用它的文件
  - 重构时批量替换多个文件中的相似模式
- **风险**：很高，因为一次动作可能改变大量代码，且依赖 AI 对整体一致性的判断。
- **权限控制**：建议保持 `ask` 或更严格的 `deny`，避免无意中引入大范围错误。

## 对比表

| 权限       | 操作范围           | 涉及文件数 | 单次修改量 | 风险等级 |
|------------|--------------------|------------|------------|----------|
| `write`    | 整个文件（覆盖）   | 1          | 大         | 高       |
| `edit`     | 文件中一个片段     | 1          | 小         | 中低     |
| `multiedit`| 多片段 / 多文件    | 1 或 N     | 大         | 很高     |

## 在 `setting.json` 中的典型配置示例

```json
{
  "permissions": {
    "write": "ask",
    "edit": "allow",
    "multiedit": "ask"
  }
}
```

你可以根据对 Claude Code 的信任程度和当前任务的敏感度调整这些值（`allow` / `ask` / `deny`）。

> 💡 **建议**：日常开发可将 `edit` 设为 `allow` 减少打断，而 `write` 和 `multiedit` 保持 `ask`，这样既能高效完成局部修改，又能避免意外的大范围变更。
