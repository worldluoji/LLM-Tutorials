# LLM Params
下面是一份 **“技术 + 人话”对照版** 的LLM参数配置指南。每个参数都会先列技术说明，再用生活化比喻解释，最后给出最佳实践与反模式。

---

## LLM 采样参数配置对照表

| 参数 | 技术作用 | 🍎 通俗解释 | ✅ 最佳实践 | ❌ 反模式 |
|------|----------|-------------|-------------|-------------|
| **Temperature** | 控制概率分布的“锐度”：低值使高概率词更易被选中（确定性高），高值使低概率词也有机会（随机性强） | **胆子大小**<br>• 低=胆小，只选最有把握的答案<br>• 高=胆大，敢尝试冷门选项<br>• 极高=胡言乱语 | 事实/代码：0.0~0.3<br>创意/对话：0.7~1.0<br>数学推理：0.2~0.5 | • 设 >1.5 导致乱码<br>• 需要JSON输出时用T>0（字段名乱变）<br>• 与极低Top-p叠加 |
| **Top-p**<br>(核采样) | 从概率和刚好超过 p 的最小动态词集中采样，过滤掉尾部低概率词 | **候选池宽窄**<br>• p=0.9：只考虑90%概率的靠谱词<br>• p=0.5：非常保守<br>• p=1.0：几乎全体词都考虑 | 通用安全值：0.9<br>短答案/实体提取：0.2~0.5<br>配合 T=0.7~1.0 使用 | • p=0.01 ≈ 贪婪解码（低效）<br>• p=1.0 失去控制作用<br>• 与极低T同时用导致双重截断 |
| **Top-k** | 强制只从概率最高的 k 个词中选择 | **候选人数**<br>• k=1：只看第一名<br>• k=40：从前40名里挑<br>• k=100：几乎不限 | 与Top-p配合：k=40~60, p=0.9<br>代码生成：k=20 | • 单独 k=1 不如直接用 T=0<br>• k<10 会错过合理词（尤其中文）<br>• k>80 几乎无效 |
| **Frequency Penalty** | 按词频降低重复概率：词出现次数越多，后续被选中的概率降得越多 | **别老说同一个词**<br>说一次“苹果”，下次说“苹果”的欲望就降一点；说越多降越狠 | 长文本：0.2~0.5<br>短答案/代码：0.0<br>聊天：0.3~0.5 | • 设 >1.0 → 强行避免合理重复（如“本文本文”）<br>• 与高Presence Penalty同时用 → 胡言乱语 |
| **Presence Penalty** | 只要词在文本中出现过一次，就整体降低其后续概率（与出现次数无关） | **别提旧话题**<br>说过一次“苹果”，后面所有提到“苹果”的概率都降低，不管说几次 | 聊天机器人：0.3~0.6<br>先调 Presence 到0.3，再加 Frequency 0.2 | • 两个 Penalty 都 >0.8 → 模型不断造新词<br>• 在代码/数学中用 → 变量名不连贯 |
| **Max Tokens** | 限制生成的最大 token 数（硬截断） | **作文最多写多少字**<br>但硬截断可能砍掉半句话 | 设为预期长度的1.2~1.5倍 | • 只靠它截断 → JSON/代码被切碎<br>• 设极大值 → 模型可能死循环 |
| **Stop Sequences** | 遇到指定字符串立即停止生成（不包含该字符串） | **喊停的暗号**<br>看到 `\n\n` 或 `###` 就收笔，保证完整收尾 | 必须设置（如 `User:`、`\n\n`、`###`） | • 不设置 → 依赖长度截断，输出不完整<br>• 设置太短符号 → 过早停止 |
| **Logit Bias** | 对特定 token 的 logit 加/减一个值，改变其被选中的概率 | **作弊加分/减分**<br>禁止词设-100，鼓励词设+5 | 强制禁止某些词（-100）<br>提升特定词概率（+1~+10） | • 调整太多token → 分布失真，模型行为怪异 |

## 通用速查表（按任务类型）

| 任务类型 | Temperature | Top-p | Top-k | Penalties |
|----------|-------------|-------|-------|------------|
| 代码/数学 | 0.0~0.2 | 1.0（不用） | 1（或不用） | 0.0 |
| 事实问答 | 0.1~0.3 | 0.9 | 40~60 | 0.0~0.2 |
| 创意故事 | 0.8~1.0 | 0.95 | 60~80 | 0.5~0.7 |
| 对话系统 | 0.5~0.7 | 0.9 | 50 | 0.3~0.5 |
| 翻译/摘要 | 0.3~0.5 | 0.9 | 40 | 0.0~0.2 |

## 核心反模式清单（一句话版）

1. ❌ 随意组合参数而不理解其概率含义  
2. ❌ 为追求“多样性”同时调高 T、p、k 并加 Penalty  
3. ❌ 生产中非0 Temperature但不设随机种子  
4. ❌ 忽略停止序列，依赖长度截断  
5. ❌ 认为同一组参数适合所有LLM（模型敏感度不同）

---

## 调试四步法（新手推荐）

1. **确定性起步**：T=0, p=1, k=1, penalty=0  
2. **观察问题**：重复→加 Presence Penalty (0.3)；太死板→升 T (0.3~0.5)  
3. **修剪噪声**：出现罕见错误词→设 p=0.9  
4. **A/B测试**：对重要任务比较2~3组参数

这样“技术+人话”对照，既保留了精确性，又让每个人都能看懂。需要再精简或扩展到其他参数（如重复惩罚的替代方案）也可以告诉我。
